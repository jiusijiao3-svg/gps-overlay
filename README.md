# GPS Overlay for Android

Pixel 7a などの Android 端末向けに開発した、純正カメラ連動型の高精度 GPS モニター ＆ Exif 自動同期アプリです。

Google のブレンド測位（Fused Location）ではなく `LocationManager.GPS_PROVIDER` から直接位置情報を取得し、
併せて `GnssStatus.Callback` で捕捉衛星数も表示します。撮影時は単発フィックスをそのまま使うのではなく、
撮影時刻近傍の複数サンプルを **精度による加重平均** で統合し、ノイズを抑えた座標を Exif に書き込みます。

## 開発の目的

スマートフォン標準の純正カメラアプリでは、撮影時に GPS 衛星を十分に捕捉できているかが画面上から判別できません。
また、GPSの単発フィックスにはマルチパスや電離層遅延などのノイズが乗るため、1点だけを信用すると精度が安定しません。

本アプリは以下の3段階でこの課題に対応します。

1. **撮影前の確認**: カメラ画面上に精度ステータス（誤差メートル数・衛星捕捉数・色判定）をオーバーレイ表示する。
2. **撮影後の統合**: 撮影時刻の前後4秒間のサンプルを、静止しているかどうかで扱いを変えて統合する。
   - 静止時: 精度の逆数二乗で加重平均し、ノイズを縮小する。
   - 移動時: 平均を取ると軌跡の重心を記録してしまうため、撮影時刻に最も近い1点をそのまま使う。
3. **自動書き込み**: 統合した座標を Exif ジオタグへバックグラウンドで自動上書きする。

## 主な機能

- **GNSS直結測位 + 衛星捕捉数表示**
  `GPS_PROVIDER` を500ms間隔で更新しつつ、`GnssStatus.Callback` で「使用中衛星数/総捕捉数」を常時表示。
- **精度に応じた加重平均 + 静止判定**
  撮影時刻の前後4秒の窓に限定し、静止時のみ加重平均。移動時は最近傍1点を採用。
- **Exif同期対象の厳格な絞り込み**
  DCIM/Camera配下、かつサービス起動後に追加された画像のみを対象にし、スクリーンショットや無関係な画像を誤って書き換えない。
- **ファイル書き込み完了のポーリング待機**
  固定遅延ではなく、ファイルサイズが連続して変化しなくなるまで待ってから読み込む。夜景合成など保存が遅い場合にも対応。
- **フローティングUI**
  ドラッグで移動、ダブルタップで終了。通知バーからも終了可能。
- **エラーのログ出力**
  例外を握りつぶさず `Log.e`/`Log.w` で記録し、`adb logcat` から追跡できる。

## 開発・ビルド環境

ローカルの Android Studio 環境を必要とせず、GitHub Actions のワークフロー内で
ソースファイル一式を生成した上で APK をビルドします。

- 言語: Kotlin
- ターゲット SDK: compileSdk 34 / minSdk 26
- ビルドツール: Gradle 8.4, AGP 8.2.2
- 主要ライブラリ: androidx.exifinterface:exifinterface:1.3.7
- CI/CD: GitHub Actions (Ubuntu-latest / JDK 17)

## 導入時の初期設定（Pixel / Android 13+）

野良 APK（サイドロード）としてインストールし、他アプリが生成した写真ファイルの Exif を直接編集するため、
初回のみ以下の権限設定が必要です。

1. **制限付き設定の解除**: 設定 → アプリ → GPS Overlay → 「︙」→「制限付き設定を許可」
2. **オーバーレイ表示の許可**: 「他のアプリの上に重ねて表示」を ON
3. **位置情報権限**: 「正確な位置情報の使用」を有効にして許可
4. **全ファイルアクセス権限（Exif上書き用）**: 初回起動時の画面で「すべてのファイルへのアクセス」を ON

## 操作方法

- **移動**: インジケーターをドラッグ
- **終了**: インジケーターをダブルタップ、または通知バーの「終了する」
- **撮影**: 通常通り純正カメラで撮影するだけで、保存完了後に自動で Exif が同期されます

## 既知の制約

- `GPS_PROVIDER` はAndroidの測位エンジンによる補正後の座標であり、擬似距離などの完全な生データではありません。
- 加重平均は撮影時刻±4秒の窓に限定しているため、この窓内にサンプルが無い場合は同期をスキップします。
- ビルドは GitHub Actions のワークフロー内でソースを生成する構成のため、通常の Git 差分レビューは効きません。
